This project focuses on developing an advanced Python-based LLM application with usage monitoring, token tracking, cost estimation, and MongoDB integration. The main objective is to connect different AI providers, generate responses, and store API usage details in a database. The project contains six files: `main.py`, `llm_client.py`, `usage_logger.py`, `test_client.py`, `.env`, and `requirements.txt`. The `main.py` file acts as the main application and allows users to choose between Google Gemini and Ollama. The `llm_client.py` file contains the provider classes, common client interface, and response handling logic. It uses an abstract class called `LLMProvider` to maintain a common structure for different AI providers. The `GeminiProvider` connects to Google's Gemini API, while the `OllamaProvider` connects to the locally running Llama 3.2 model.

The project introduces an `LLMResult` data class to store generated text, input tokens, and output tokens. The `LLMClient` measures response time, calculates total token usage, estimates API costs, and records successful or failed requests. It also includes retry mechanisms to handle temporary errors. The `usage_logger.py` file contains the `UsageLogger` class, which connects to MongoDB and stores API usage information in the `llm_monitoring` database under the `api_usage` collection. It records provider name, model, token counts, latency, estimated cost, status, and timestamp. The `test_client.py` file uses Python's `unittest` framework and fake provider and logger classes to test response generation and usage logging. The `.env` file stores the Gemini API key, MongoDB connection URI, and input and output pricing values. The `requirements.txt` file contains the required packages: `google-genai`, `requests`, `python-dotenv`, `pymongo`, and `pytest`.

To execute the project, install the dependencies using `pip install -r requirements.txt`. Configure the Gemini API key and MongoDB URI in the `.env` file. Run the application using `python main.py`, select either `gemini` or `ollama`, and enter your question. For Ollama, the Llama 3.2 model must be installed and running locally. The application connects to MongoDB and automatically saves usage information after each request. Unit tests can be executed using `python -m unittest test_client.py`. Overall, Week 3 provides an understanding of LLM integration, MongoDB database connectivity, token tracking, API cost estimation, response-time monitoring, error handling, retry mechanisms, and automated unit testing using Python.
